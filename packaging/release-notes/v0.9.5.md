# Licasa 0.9.5

Licasa 0.9.5 focuses on safer editing and saving, a more capable export workspace,
clearer settings, smoother fullscreen panels and stronger automated verification.

This release includes the changes since
[0.9.0](https://github.com/sanxchep/licasa/releases/tag/v0.9.0).

## Highlights

- Save safely across multiple windows without resetting another window's edits
  or silently applying them to an original that has changed on disk.
- Confirm before overwriting an original, or use the separate **Save as a copy**
  action to retain the original file.
- Export through a single format chooser with settings tailored to 14 formats,
  linked dimensions and an estimated output size.
- Type exact values directly into adjustment and export controls.
- Use fullscreen Settings and Editor panels with consistent exclusion, closing
  animations, keyboard behavior and information-overlay transitions.
- Run a shared CI verification graph with explicit publication boundaries,
  stronger package evidence and expanded editor/file-safety regressions.

## Safer saving and independent windows

Saving, copying or exporting from one window no longer clears another window's
adjustments, crop, undo/redo history, image selection or notices. Image and Motion
Photo frame-save results identify their initiating window, and closing that
window does not transfer ownership to another viewer.

Late, unsolicited or duplicate results cannot reset a replacement editing
session after navigation. A busy rejection belongs to the rejected requester,
and completion preserves changes made after the save request was captured.

The viewer also records the version of the source file used for editing. If
another window overwrites that file, stale saves are refused with a reopen
message. The other window retains its edit values, history and pending numeric
input rather than silently applying those edits to an already modified source.
Reopening establishes a new baseline; this does not create private source-file
copies for every window. Source identity is checked again before an atomic
write commits, protecting against replacement during processing.

Save failures preserve the original and any existing destination. Tests exercise
mid-write failure, denied commit, source replacement, missing destinations,
retry, aliases and request-owner lifetime.

## Save, Save as a copy and overwrite consent

**Save** opens a compact amber warning above the footer explaining that the
original will be replaced. **No** is the initial focus, keyboard focus stays
within the confirmation, and declining or dismissing it does not save. Changes
to the source, tool or save eligibility invalidate obsolete confirmation.

**Save as a copy** replaces the old footer Export label. It keeps the edited
image's full output resolution and uses the source writer where supported,
independently of custom Export-tab scale or encoding choices. Supported density
and color-profile information is retained where the writer can store it; this
is not a promise to preserve every metadata field. Reader-only formats use the
supported fallback rather than pretending to have a writer.

Copy/export dialogs select the suggested suffix and matching filter, reset the
suggestion when reopened and capture an immutable request. A later source change
cannot redirect an old request into the newly opened image. Copy-only operations
reject destinations that alias the original.

The redundant footer caption and **Hold Original** button are removed. Footer
spacing and the panel's continuous rounded outline now follow the Settings
layout. On the Export tab, Save and Save as a copy slide out of view, leaving the
dedicated Export action.

## Export workspace and formats

A single keyboard-accessible chooser offers **Same as source** and the formats
available in the bundled writer set: **PNG, JPEG, WebP, TIFF, BMP, ICO, CUR, ICNS,
PBM, PGM, PPM, WBMP, XBM and XPM**. Reader support for other formats does not imply
export support.

Each format displays its relevant settings and concise explanations. Settings
are remembered separately while switching formats and reset for a new image.

| Format | Settings and behavior |
| --- | --- |
| PNG | Fast, Balanced and Smallest compression choices, with unchanged lossless quality; color, grayscale or indexed palette; palette size, dithering, transparency and background controls. |
| JPEG | Quality, progressive loading, optimized encoding, color/grayscale and white/black transparency background. |
| WebP | Lossy quality or lossless encoding; the quality control hides when lossless is selected; transparency and background controls. |
| TIFF | LZW or uncompressed encoding, color/grayscale, transparency and background controls. |
| BMP | Color, grayscale or indexed palette, palette size/dithering and transparency background. |
| ICO | Legal icon-canvas sizes, Fit/Fill framing and transparency/background controls. |
| CUR | Icon-canvas/framing controls plus horizontal and vertical cursor hotspots; both coordinates stay inside the selected canvas. The output has a real CUR header. |
| ICNS | Legal canvases through 1024 × 1024, Fit/Fill framing and transparency/background controls. |
| PBM | Binary or plain-text encoding, black/white threshold, dithering, inversion and transparency background. |
| PGM | Binary or plain-text grayscale encoding and transparency background. |
| PPM | Binary or plain-text RGB encoding and transparency background. |
| WBMP / XBM | Monochrome threshold, dithering, inversion and transparency background, including odd-width/padding handling. |
| XPM | Indexed palette size, dithering, transparency threshold and background controls. |

Non-icon exports have a **1–200%** output scale, linked width/height entry and a
one-pixel minimum. Dimensions remain proportional to the edited image, including
crop and rotation. Icon formats use their legal square canvas presets instead.
**Pixel-art scaling** selects crisp nearest-neighbor scaling; the default uses
smooth scaling. Supported photo formats offer **Convert to sRGB**; supported
density fields accept **0–2400 DPI**, with zero retaining source density.

The green bordered Export action shows the chosen format, dimensions and
estimated size, and fills green on hover/focus. Size estimation uses the actual
encoding path and effective options. Old replies for another owner, source,
revision, tool or closed panel cannot replace the current label. Failed estimates
show an unavailable state, and a successful retry clears the corresponding old
estimate error. Estimates are not a guarantee that a later changed source or
another runtime will produce identical bytes.

The native writer validates formats/options, dimensions, resource limits, icon
sizes and hotspots before committing output. Palette dithering now changes the
encoded result as intended, and XPM transparency survives encoding. TIFF checks
respect associated-alpha rounding rather than requiring unsupported hidden-RGB
preservation.

A failed PNG output also avoids a Qt 6.4 encoder cleanup leak. Encoding errors
still fail the save and cancel its atomic output; the workaround does not buffer
the whole encoded image or turn failed writes into successful saves.

ICNS exports can be fully decoded on both supported Qt runtime profiles. Their
reader cannot report ICNS source dimensions before decoding, so full-resolution
editing/copy admission for that source remains safely refused rather than
bypassing the image-memory guard.

## Exact numeric entry and editor interaction

Every adjustment value is an editable field, synchronized with its slider:

- Exposure, Contrast, Highlights, Shadows, Saturation, Vibrance, Warmth and Tint:
  **−100 to 100%**.
- Sharpen and Vignette: **0–100%**; Soften: **0–35%**.
- Export scale: **1–200%**; JPEG quality: **1–100**; lossy WebP quality: **1–99**.
- Monochrome/transparency thresholds: **0–255**, displayed in raw units.
- Density: **0–2400 DPI**; cursor hotspots stay within the selected canvas.

Decimal-point input, fractional precision, clamping and minimum/maximum values
are consistent. Partial, non-finite, overflow and invalid entries restore the
current value instead of turning into an unintended zero. Enter/numpad Enter,
Tab, Backtab, blur and Escape have defined commit/cancel behavior.

Save/Copy shortcuts work while a field is focused and capture its valid draft
before consent or dialog creation. Pointer, keyboard and accessibility actions
follow the same rule. Tool/format changes commit valid pending input; explicit
reset, undo and source replacement retire obsolete drafts. Dirty text retains
local text undo, while committed fields route image undo/redo to the editor.

All visible Looks have explicit state/history checks. Crop presets, rotation and
mirror history remain undoable. Impossible custom crop ratios are rejected
without silently substituting a different shape or altering the draft; accepted
ratios account for unavoidable output-pixel rounding.

Expanded Advanced content and resized drawers keep the focused control visible.
Wheel scrolling is contained at both ends of the drawer rather than zooming the
image beneath it. Hidden footer actions are excluded from keyboard navigation.

## Fullscreen panels, settings and visual polish

Settings and Editor are mutually exclusive. Opening one slides the opposite
launcher beyond its screen edge; pointer and keyboard attempts cannot open the
other drawer during the open/close transition. Outside click, close controls and
otherwise unhandled arrow keys dismiss the drawer consistently, while fields,
sliders and dropdowns retain their own navigation.

Settings remains above notifications and close controls throughout its closing
animation. The editor also stays above notifications in narrow layouts. Opening
Editor slides the enabled filename/resolution/zoom overlay downward out of view;
closing it restores the overlay without changing the user's preference. Reduced
motion remains supported.

Settings copy is shorter and more explicit:

- Remove the introductory Settings and rendering-quality subtitles.
- Describe Background process as keeping a lightweight process open, starting at
  the next login.
- Distinguish **Full screen transparency grid** from **Floating transparency
  grid**, with matching descriptions.
- Present **Maximum working memory per image** directly, with its estimated image
  budget and the bounded-preview explanation.
- Present Quit, source and issue-report actions as separate bordered sections
  below Advanced, with matching hover fills. The red Quit action explains that
  it closes the viewer and background processes. About Licasa is last.

## CI/CD, package checks and release boundaries

The shared non-publishing verification graph now selects coverage by event:

- Every main push, ready code PR to main, merge group and valid version tag gets
  FULL verification. A tag does not publish a release.
- Development branch pushes, draft PRs and PRs targeting another branch get FAST
  feedback. Ready prose-only changes use the narrowly defined DOCS path; unknown,
  mixed, added/deleted and release-note changes select FULL.
- Manual verification defaults to FULL and pins the requested source. Scheduled
  drift checks and a weekly cold-cache comparison are separate from publication.
- Fork/Dependabot verification uses read-only permissions and no publication
  secrets. Reviewed policy controls selection and required completion checks.

The shared FULL graph checks workflow expressions/graphs and shell syntax, source
formatting, support/public-file contracts, Python regressions, Release/sanitizer
source profiles and canonical native/package qualification. Motion Photo/FFmpeg
and JP2 paths are included in source verification with matching sanitizer media
plugins and the necessary build dependencies. Real RPM lifecycle/bootstrap
preflight runs before expensive package work. Required job failures, missing
artifacts or unexpected skips cannot become a successful FULL receipt.

Cold runs exclude binary/compiler/build-layer reuse and only claim reproducibility
when a valid same-source reference exists. Scoped retries retain validated source
and build evidence and rerun only eligible failed targets. PR metadata-only edits
cannot cancel a still-needed verification for an unchanged merge result.

The release builds and qualifies packages through that shared graph and stages
the same immutable artifacts for the guarded prerelease/edge and stable flows.
It does not rebuild different bytes after qualification. Package hardening checks
inspect the ELF behind its launcher. Unsupported Ubuntu rejection reports must
prove the specific rejection and match the actual package hash; arbitrary install
failure or unrelated evidence is insufficient.

Pinned actionlint preparation/checks, event rules, result receipts, cache
fingerprints, artifact retention and CODEOWNERS are covered by regressions.
Hosted protection settings have an inspect/plan/apply workflow; preparing those
rules does not enable them or change repository administration automatically.
Ordinary CI can verify an already released version; version uniqueness belongs
to release preparation.

The native Ubuntu/Qt 6.4 and Debian/Qt 6.8 stacks remain separate. Export uses
the existing Qt writers and bundled/runtime codecs; it does not add AVIF/HEIF/RAW
writers or widen package/platform support. Existing runtime-module inventories,
codec locks and package dependency declarations remain authoritative.

Installation guidance has also been clarified since 0.9.0: fully quit legacy
copies before replacing them, keep package families and installation ownership
distinct, and distinguish automatic Store Snap refresh from manually installed
downloads. Background mode itself does not download application updates.

## Regression coverage

Coverage connects real editor input to Main state, request snapshots, native
encoding and files on disk. It includes all 11 adjustments, Looks/history,
crop/transform composition, every export format's UI and encoded settings,
estimate freshness, overwrite consent, real two-window saves, accessibility
actions, short/narrow layouts and doubled display scale.

Controlled write/commit failures preserve existing files and permit retry.
Fixed-seed mixed action sequences use an independent history oracle, and selected
deliberate bugs are required to fail relevant tests. New suites participate in
normal CTest/core verification rather than living only in a manual checklist.
