# Licasa 0.9.6 release notes

Licasa 0.9.6 improves opening performance for large images and fixes large HEIC
files that failed to load in 0.9.5.

## Faster opening

- Deferred loading of the Editor and fullscreen Settings panels until needed,
  reducing startup work before the first image.
- Added reuse of admitted full-resolution decodes during the preview-to-full
  transition, avoiding repeated reads and decoding across several formats.
- Added early dimension reading for eligible SVG files without parsing the
  complete document, plus reuse of the rendered full image during the
  preview-to-full transition.
- Added an optional bounded decompression path for large SVGZ files while
  retaining Qt's SVG parser and renderer. Unsupported envelopes, failed
  checksums and files outside the limits use the original reader.
- Added direct decoding of supported XPM palettes and reuse of the full raster.
  Other XPM inputs use the Qt fallback.
- Eliminated duplicate WebP decoding and unnecessary pixel-layout conversion
  for opaque images.
- Reduced JPEG 2000 preview/full contention and improved pixel packing.

Final image quality is preserved. A near-size HEIC thumbnail may be enlarged by
up to 1% per axis for the temporary preview; full detail still uses the native
image. The thumbnail benefit depends on the viewport size.

## Compatibility and loading fixes

- Fixed bounded HEIC input admission for large encoded images. Seven HEIC,
  HEIF and related test cases that failed in the public 0.9.5 build now render
  successfully.
- Enabled reuse of decoded image data for supported still-image AVIFS, HEICS
  and HEIFS aliases. These tests cover still images, not animation playback.
- Fixed terminal decode errors leaving the viewer stuck on Loading when the
  active request key changed.
- Preserved cancellation, file identity and memory limits in optimized paths.
  Large retained rasters are consumed once and cleared when no longer needed.

The reference is the published
[v0.9.5](https://github.com/sanxchep/licasa/releases/tag/v0.9.5) from 30 October 2026.

desktop and 20 CPUs, with fresh application settings/cache and warm OS caches.
The clock includes the real injected double-click, dispatch and native program
startup. AppRun, FUSE mounting and managed-package wrappers are excluded from
both builds. Physical monitor presentation is outside the measurement scope.

Every successful opening was checked for a native 10,000 × 10,000 full raster,
with 20 measured openings per successful build/case. Both screening attempts
were retained for the seven cases that failed in 0.9.5; timing and improvement
are marked as unavailable. All 456 comparable timing checks passed.

For DNG without a preview, the complete paired comparison was repeated at
matching 1920 × 1080 window sizes. Its improvement is calculated from that
replication alone. All other 44 cases used matching 1920 × 1080 windows throughout.
