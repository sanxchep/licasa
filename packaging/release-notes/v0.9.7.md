# Licasa 0.9.7 release notes

## Keyboard shortcuts

- Added a keyboard shortcuts window, available with **F1** or from **Settings →
  Keyboard shortcuts**, with grouped actions and clear arrow-key labels.
- Added keyboard navigation and screen-reader descriptions for shortcut help.
  Closing help restores focus and the Settings scroll position.
- Preserved unfinished numeric edits while shortcut help is open and blocked
  background viewer actions until it closes.
- Updated Swedish translations for the shortcut interface.

## Image opening

- Improved first-open startup by compiling shared QML JavaScript during the
  build, avoiding runtime compilation and synchronous cache writes before the
  first image.
- Fixed a delay when a full-resolution image finished preloading before the
  viewer requested it.
- Fixed initial transparency in QOI decoding and improved QOI pixel conversion
  and preview sampling.

## AppImage compatibility

- Added an Ubuntu 22.04 build baseline for the AppImage, lowering its glibc
  requirement to 2.35 while keeping the private Qt 6.4.2 runtime and codec fixes.
- Added offline Ubuntu 22.04 AppImage checks on virtual X11 and Wayland desktops,
  alongside Ubuntu 24.04 and Debian 13 package checks. The native Ubuntu `.deb`
  continues to target Ubuntu 24.04.
- Improved AppImage dependency and ABI checks, runtime source verification and
  build-tool compatibility with Python 3.10.

## Verification reliability

- Fixed package checks that could disappear when Python optimization was enabled.
- Fixed failed package-verification reruns retaining a previous success report.
- Improved lifecycle test startup checks to require a response from the launched
  process before proceeding.

## Performance comparison: 0.9.6 → 0.9.7

The reference is the original published [v0.9.6](https://github.com/sanxchep/licasa/releases/tag/v0.9.6) AppImage executable and its shipped runtime. The candidate is the tested 0.9.7 production executable from [4980a37](https://github.com/sanxchep/licasa/commit/4980a373f01820d380009d68f99234cf21d3f55f), with the qualified Ubuntu 22.04 Qt 6.4.2 and codec runtime. The application executables were not recompiled or modified for measurement.

The comparison uses an Intel Core i9-13900H, 20 CPUs and an isolated 1920 × 1080 X11 software desktop. Each file has a native 10,000 × 10,000 raster. Each build/case has two warmups and 20 measured openings, in seeded alternating order, with fresh application settings/cache and warm OS caches.

All six columns start at the actual file-manager double-click, including dispatch and native application startup. Decoded-ready signals and visible software frames are separate endpoints. AppRun, FUSE mounting, managed-package wrappers and physical monitor presentation are excluded from both builds. The installed Local app is outside these measurements.

The campaign retained **1,980 formal openings**, including **1,800 measured openings** and **180 warmups**. Of 528 comparable median/p95 timing checks, **477 passed** and **51 exceeded the unchanged limits** (median: reference + max(3%, 5 ms); p95: reference + max(5%, 10 ms)). Failed or incomplete cases remain unavailable rather than receiving an invented percentage.

Each cell shows **0.9.6 seconds → 0.9.7 seconds (reduction %)**. Negative reductions mean slower. All columns share the same click origin; do not add them.

The published RGBA QOI decoder produces pixels that differ from the independent PNG reference; 0.9.7 matches that reference. Its timings remain visible, labelled **pixels differ**, with no speedup percentage or accepted timing gate for unequal results. RGB QOI pixels match the PNG reference in both builds.

Checks above the limits occur in BigTIFF, TIFF (.tif and .tiff), SVGZ, RGB QOI and XBM. The tables retain every faster, unchanged and slower value; the candidate has not passed the complete release-to-release performance limits.
